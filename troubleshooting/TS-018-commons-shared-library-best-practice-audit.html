Điểm mạnh · đã đạt best practice

Cái gì đang làm đúng

  • ✓Ranh giới package rõ (SRP) — api/exception/util/web, mỗi type một trách nhiệm.
  • ✓DTO immutable — toàn bộ envelope là record + @JsonInclude(NON_NULL); PageResponse defensive-copy List.copyOf(items).
  • ✓Factory rõ nghĩa — ok/noData/fail; noData(String) đặt tên tránh ambiguity với ok(T) (đúng TS-004 PROPOSAL-003).
  • ✓Cây exception hợp banking — IntegrationException (extRef/corrId), UnknownResultException (txRef, HTTP 202) → đúng ngữ cảnh đối soát giao dịch/fintech.
  • ✓Handler phủ đủ ma trận lỗi input — validation, constraint, type-mismatch, unreadable body, method-not-supported, catch-all.
  • ✓Chống log-injection — sanitize() strip \n/\r trước khi log (best practice bảo mật).
  • ✓Scope provided cho servlet/validation/spring-data → không ép version transitive lên consumer.
  • ✓Publish chuẩn — MIT, SCM, sources+javadoc jar, DevSecOps (SpotBugs+FindSecBugs, OWASP DC, JaCoCo, Sonar).
  • ✓Deprecation đúng chuẩn — TraceIdFilter đánh @Deprecated(forRemoval=true) + ghi chú migration.
  • ✓Pagination có bound an toàn — PageableFactory: MAX_PAGE_SIZE=100, clamp, page 1→0-based.

Cao · G1

Thiếu Spring Boot auto-configuration

Repo commons
GlobalExceptionHandler @RestControllerAdviceTraceIdFilter @Componentjar META-INF (no .imports)

2 bean chỉ load được vì mọi service đặt main class ở package vn.conghung, lib ở vn.conghung.common.* → component-scan tình cờ với tới. Lib không tự-đóng-gói/portable: consumer ở package khác sẽ âm thầm mất handler → HTTP 500 (đúng sự cố TS-001). TS-001 đã kết luận cách đúng là auto-config; repo lại chọn "chuẩn hoá package root" — coupling ẩn.

FixThêm class @AutoConfiguration @Import(GlobalExceptionHandler.class) + file META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports. Service chỉ cần có dependency là handler tự load, không phụ thuộc package root. 
# AutoConfiguration.imports
vn.conghung.common.autoconfigure.CommonsAutoConfiguration
Trade-offCách hiện tại đơn giản & "chạy được", nhưng đổi bằng tính portable + rủi ro regression im lặng cho service tương lai. Auto-config là chuẩn ngành cho shared starter.
TB · G2

Lệch timezone & bypass factory khi dựng envelope

Commons + repo này
ApiResult.java (ICT_ZONE)OrderExceptionHandler.java:25 (UTC)

ApiResult đóng dấu requestDateTime theo Asia/Ho_Chi_Minh, nhưng OrderExceptionHandler dựng envelope bằng constructor thô với ZoneOffset.UTC → cùng field, cùng API surface, 2 zone khác nhau; service còn bypass factory.

FixZone-policy (commons): thống nhất UTC + inject Clock (testable). Handler (repo này): đi qua factory. Gộp với debt timezone toàn cục đã ghi ở TS-017 M3/M4.
Trade-offICT→UTC là breaking nhẹ cho client parse local-time → làm đồng loạt commons + account + product + order, kèm changelog.
TB · G3

Phụ thuộc stereotype-scan (@Component trên filter)

Repo commons
web/TraceIdFilter.java:21

Filter no-op (đã @Deprecated forRemoval) nhưng vẫn @Component → bị auto-đăng-ký vào servlet filter chain (mắt xích vô ích). Library không nên dùng stereotype phụ thuộc scan để đăng ký hạ tầng — cùng gốc với G1.

FixChuyển sang auto-config/conditional bean, hoặc xoá hẳn ở major kế tiếp (đường đóng đã rõ nhờ forRemoval).
TB · G4

Thứ tự @RestControllerAdvice không tường minh

Repo commons
GlobalExceptionHandler (catch-all Exception, no @Order)

Advice global có catch-all @ExceptionHandler(Exception.class) nhưng không @Order; advice service cũng không. Hiện exact-match thắng nên đúng, nhưng catch-all không xếp thứ tự là rủi ro tiềm ẩn (có thể che handler cụ thể hơn khi thứ tự bất định).

FixĐánh @Order(Ordered.LOWEST_PRECEDENCE) cho advice global → advice service luôn ưu tiên xác định. Chi phí ≈ 0.
Thấp–TB · G5

Parse chuỗi message exception dễ vỡ

Repo commons
GlobalExceptionHandler.resolveDetailMessage()parseMismatchedInput()

Bóc HttpMessageNotReadableException.getMessage() bằng substring ("through reference chain:", "from String \"", type '...'). Phụ thuộc format text Jackson/Spring theo version & locale → dễ gãy khi nâng cấp (Boot 4.x / Jackson 3.x).

FixDùng cause có cấu trúc: InvalidFormatException/MismatchedInputException, getPath() (field), getTargetType() (type) — ổn định qua version.
Thấp · G6

Test coverage chưa rõ / không ship

Repo commons
sources jar: chỉ có mainJaCoCo cấu hình nhưng không thấy test

GlobalExceptionHandler là code blast-radius lớn nhất toàn hệ (mọi service phụ thuộc contract). Thiếu test ma trận exception→status là rủi ro cho toàn fleet.

FixThêm contract test (@WebMvcTest/standalone MockMvc): mỗi exception → đúng status + responseCode + shape ErrorDetail.
Thấp · G7

Version chưa quản lý tập trung

Repo này
order/product/account/mail — pom riêng

Mỗi service lặp <conghung-commons.version>0.3.0 → dễ trôi version (một service quên bump → chạy contract khác).

FixKhai 1 lần ở parent pom <dependencyManagement>, service khai <dependency> không kèm version. Ngoài scope doc-only → chỉ khuyến nghị.
Thấp · G8

ErrorDetail(Object) không kiểu + nullness không nhất quán

Repo commons
api/ErrorDetail.javajspecify chỉ ở TraceIdFilter

Object details mất type-safety, khó document cho client (thực tế thường là List<ValidationError>). Annotation nullness không đồng bộ toàn module.

FixDocument rõ shape của details hoặc dùng type hẹp hơn; chuẩn hoá nullness bằng package-info @NullMarked (jspecify).
